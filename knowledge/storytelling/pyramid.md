# Pyramid Principle

## Purpose

Define hierarchical communication structure: answer → supporting arguments → evidence.

## Scope

Default for: executive, decision, recommendation, synthesis presentations.

**Not for:** Exploratory learning, pure chronological narrative, open-ended research.

## Structure

```
LEVEL 1: ANSWER / GOVERNING THOUGHT
  │  (One declarative sentence — the "so what?")
  │
  ├─ LEVEL 2: KEY ARGUMENTS (3–5 max, MECE)
  │     │
  │     ├─ Argument A
  │     ├─ Argument B
  │     └─ Argument C
  │
  └─ LEVEL 3: EVIDENCE FOR EACH ARGUMENT
        │
        ├─ Data, facts, examples, authority
        └─ (Each argument independently supported)
```

## Rules

### MECE (Mutually Exclusive, Collectively Exhaustive)

- **MUST:** Arguments at same level are mutually exclusive (no overlap)
- **MUST:** Arguments collectively exhaust the support for the answer
- **Test:** "If these are true, does the answer necessarily follow?"

### Vertical Logic

- **MUST:** Each level summarizes the level below
- **MUST:** Each level raises questions answered by the level below
- **Flow:** Answer → "Why?" → Arguments → "How do you know?" → Evidence

### Horizontal Logic

- **MUST:** Arguments at same level are same type (all reasons, all steps, all categories)
- **MUST NOT:** Mix reasons with steps with categories at same level

## Slide Mapping

| Pyramid Level | Slide Type | Count Guidance |
|---------------|------------|----------------|
| Answer | Executive summary / Recommendation | 1 slide |
| Key Arguments | Assertion-evidence slides | 1 per argument (3–5 slides) |
| Evidence | Detail slides (chart, table, diagram) | As needed per argument |
| Appendix | Reference / backup | Unlimited (not presented) |

## When to Use

| Context | Use Pyramid? |
|---------|--------------|
| Executive decision | YES — answer first |
| Board recommendation | YES — governing thought upfront |
| Strategy synthesis | YES — integrate multiple analyses |
| Investor pitch (traction) | YES — thesis → proof points |
| Technical deep-dive | NO — use assertion-evidence |
| Training/learning | NO — use educational journey |
| Incident retrospective | NO — use chronological |
| Exploratory research | NO — use research narrative |

## Exceptions

### Exploratory Learning
- **When:** Audience must discover the answer themselves
- **Structure:** Question → Investigation → Emerging insight → Answer
- **Rationale:** Premature answer blocks learning

### Bottom-Up Synthesis (Rare)
- **When:** Building consensus from shared data
- **Structure:** Shared evidence → Grouped observations → Synthesized answer
- **Rationale:** Answer not yet known or contested

## Anti-Patterns

- **Inverted pyramid:** Evidence first, answer last (executive audiences disengage)
- **Non-MECE arguments:** Overlapping reasons, gaps in logic
- **Too many arguments:** >5 at one level (exceeds working memory)
- **Mixed logic types:** Reasons mixed with steps at same level
- **Unsupported arguments:** Assertion without evidence at level 3

## Handoff to Other Layers

- **Narrative-patterns:** Pyramid is one pattern in the library
- **Reasoning (select_narrative):** Chooses pyramid when objective=decision, audience=executive
- **Slide-types:** Maps pyramid levels to slide archetypes
- **Evaluation:** Checks MECE, vertical/horizontal logic, answer-first
