# Presentation Principles

## Purpose

Define the fundamental principles governing every presentation decision. These principles are universal — they apply regardless of presentation type, audience, or context.

## Scope

All presentations generated by this system.

## Core Principles

### 1. Audience-First Design

**MUST** analyze audience before any design decision.

- **Decision rule:** IF audience expertise is low, THEN increase explanation density and signalling
- **Decision rule:** IF audience is executive, THEN lead with answer/implication
- **Decision rule:** IF audience is technical, THEN include mechanism detail and evidence

### 2. Objective-First Design

**MUST** define the presentation objective before slide structure.

- **Decision rule:** IF objective is decision, THEN use pyramid or problem-solution narrative
- **Decision rule:** IF objective is learning, THEN use educational learning journey with segmentation
- **Decision rule:** IF objective is alignment, THEN use comparison or transformation narrative

### 3. Message Before Visual

**MUST** determine slide message/assertion before selecting visual representation.

- **Rule:** Visual representation serves the message; never the reverse
- **Anti-pattern:** Choosing a chart type because it "looks good" without a message to communicate

### 4. Truthfulness

**MUST NOT** fabricate, exaggerate, or misrepresent facts, data, sources, or conclusions.

- **Rule:** Every quantitative claim MUST have a traceable source
- **Rule:** Distinctions between fact, inference, assumption, and projection MUST be preserved
- **Rule:** Uncertainty MUST be communicated when material

### 5. Communication Effectiveness

**SHOULD** maximize the probability that the audience understands the intended message.

- **Metric:** Can the audience state the key message of each slide after viewing?
- **Rule:** If a slide fails this test, it MUST be revised

### 6. One Dominant Communication Job Per Substantive Slide

**MUST** assign exactly one primary communication purpose to each substantive slide.

| Slide Purpose | Description |
|---------------|-------------|
| Assert | Make a declarative claim with evidence |
| Compare | Contrast two or more items on defined criteria |
| Explain | Show how something works (mechanism, process) |
| Decide | Present options with trade-offs for a decision |
| Navigate | Orient audience (agenda, section divider, summary) |
| Reference | Provide lookup data (appendix, detailed table) |

**EXCEPTION:** Navigation and reference slides may have multiple items.

### 7. Content Reduction

**MUST** reduce content to the minimum needed for the audience to grasp the message.

- **Repair order for overflow:**
  1. Remove unnecessary content
  2. Rewrite for conciseness
  3. Restructure (split message across slides)
  4. Split slide
  5. Change layout variant
  6. Controlled typography reduction (last resort)

**NEVER** solve overflow by making text unreadable.

### 8. Evidence-Based Communication

**MUST** support substantive assertions with appropriate evidence.

- **Evidence hierarchy:** Primary data > Peer-reviewed study > Industry report > Expert opinion > Anecdote
- **Rule:** Decorative imagery is NOT evidence
- **Rule:** Evidence MUST be visually integrated with the assertion (assertion-evidence pattern)

### 9. Consistency

**MUST** maintain systematic consistency across the deck.

- **Design system:** All slides inherit centralized tokens (typography, colour, spacing, grids)
- **Narrative:** Terminology, framing, and level of abstraction consistent
- **Visual:** Chart conventions, diagram styles, label formats consistent

### 10. Accessibility

**MUST** meet accessibility requirements as part of generation, not post-hoc.

- **Release blockers:** Unreadable essential text, colour-only meaning, missing alt text on meaningful visuals, broken reading order

### 11. Render-and-Inspect Principle

**MUST** render and inspect the generated PPTX before considering it complete.

- **Checks:** Clipping, overflow, font substitution, alignment drift, colour rendering, animation timing
- **Rule:** Successful file export ≠ communication success

### 12. Universal vs. Contextual Rules

| Rule Type | Description | Examples |
|-----------|-------------|----------|
| Universal | Apply to ALL presentations | Truthfulness, accessibility, one job per slide |
| Contextual | Apply based on presentation type, audience, objective | Narrative structure, evidence burden, chart defaults |

**Rule:** Contextual rules specialize universal rules; they MUST NOT contradict them.

## Decision Sequence

```
request
→ context (topic, constraints, assets)
→ audience (role, expertise, expectations)
→ objective (what must this achieve)
→ narrative (which structure serves objective + audience)
→ slide message (one per substantive slide)
→ evidence (what supports each message)
→ representation (chart, diagram, table, text)
→ layout (grid, hierarchy, spacing)
→ styling (design system tokens)
→ generation (PPTX production)
→ evaluation (content, story, visual, accessibility, rendering, coherence)
```

**Critical:** Visual styling (step 9) MUST NOT precede semantic reasoning (steps 1-7).

## Handoff to Other Layers

- **Reasoning layer** implements this decision sequence as executable procedures
- **Generation layer** produces PPTX following layout and styling decisions
- **Evaluation layer** validates against these principles
