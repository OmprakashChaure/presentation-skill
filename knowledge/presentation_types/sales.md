# Sales Presentation Type

## Purpose

Define type-specific policies for sales presentations.

## Scope

Discovery follow-up, solution proposal, demo, proof-of-concept, renewal/expansion, competitive bake-off.

## Core Policies

### Customer Problem First

- **MUST** open with customer's problem (not your product)
- **Format:** "You told us: [Problem] — Impact: [Quantified cost/risk]"
- **Rule:** If you didn't discover it, don't present it — ask first

### Desired Outcome

- **MUST** articulate: "What good looks like for you"
- **Format:** "Goal: [Metric] from [Current] to [Target] by [Timeline]"
- **Rule:** Outcome = Customer's language, not your feature list

### Value Proposition Before Solution

- **MUST** state: "We help [Customer] achieve [Outcome] by [Unique approach]"
- **Differentiation:** Why this approach vs alternatives (build, compete, status quo)
- **Rule:** Features only appear as proof of value prop

### Solution Mapped to Problem

- **MUST** map: Problem component → Solution capability → Outcome impact
- **Format:** Table: [Problem] | [Capability] | [Evidence] | [Outcome Delta]
- **Anti-pattern:** Feature tour unconnected to discovered problems

### Evidence & Proof

| Claim Type | Required Proof |
|------------|----------------|
| Outcome achievement | Customer case study (same segment/size) with metrics |
| Capability works | Live demo / sandbox / recorded walkthrough |
| Integration | Architecture diagram + reference customer |
| Security/Compliance | Certifications, audit reports, DPA |
| Implementation | Timeline, resources, customer effort, go-live criteria |

### Objection Handling

- **MUST** proactively address: Top 3–5 anticipated objections
- **Format:** "Concern: [Objection] → Reality: [Evidence/Context] → Mitigation: [Action]"
- **Rule:** Don't wait for objection — address in deck

### Next Action — Concrete

- **MUST** end with: Specific next step, Owner, Timeline, Success criteria
- **Format:** "Next: [Customer action] by [Date] → We will [Our action] → Success: [Measurable]"
- **Rule:** No "let's stay in touch" / "happy to discuss"

## Slide Type Defaults

| Purpose | Slide Archetype |
|---------|-----------------|
| Customer problem | Assertion-Evidence (their data) |
| Desired outcome | KPI/Target comparison |
| Value prop | Assertion-Evidence (differentiation) |
| Solution mapping | Comparison table (Problem→Capability) |
| Demo | Image-led (screenshot/architecture) |
| Case study | Assertion-Evidence (customer results) |
| Objection handling | Comparison (Myth vs Reality) |
| Pricing/ROI | Table + Chart (Payback) |
| Next steps | Recommendation slide |

## Narrative Default

- **Primary:** Problem-Solution (Context → Problem → Outcome → Value Prop → Solution → Evidence → Objections → Next Step)

## Design Adaptations

- **Density:** Low-Medium — conversational, not dense
- **Branding:** Customer's logo/colours subtly (not yours)
- **Personalization:** High — every deck tailored to account
- **Appendix:** Technical specs, security, legal, implementation detail

## Anti-Patterns (MUST PREVENT)

- Feature dumping (feature list without problem mapping)
- Generic "we're the best" without differentiation evidence
- No customer-specific discovery reflected
- Demo without narrative context
- Case studies from irrelevant segments
- Pricing without ROI/payback
- No clear next step with ownership

## Handoff to Other Layers

- **Reasoning:** Selects problem-solution; enforces customer-first framing
- **Narrative-patterns:** Problem-solution with sales-specific components
- **Slide-types:** Problem, Value Prop, Solution Mapping, Case Study, Objection, Next Step
- **Visualization:** ROI charts, payback, comparison tables
- **Evaluation:** Checks: Customer problem first, outcome quantified, solution mapped, evidence relevant, objections addressed, next step concrete
